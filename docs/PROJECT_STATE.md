## وضعیت معماری
- هسته منو در `release/v6/` نگهداری می‌شود.
- اصلاحات مرحله‌ای در patchهای نسخه‌های V7، V32، V33 و V34 اعمال می‌شوند.
- `index.html` نسخه‌های patch فعال را به ترتیب بارگذاری می‌کند.
- سفارش‌ها در حالت محلی با LocalStorage پشتیبانی می‌شوند و معماری پروژه برای API مرکزی نیز آماده است.
- مسیر سرور مرکزی در `dragon-cafe-server/` قرار دارد.
- PWA با `manifest.webmanifest` و `sw.js` پشتیبانی می‌شود.

## تغییرات فعال V34
### پیش‌نمایش محصول
- کلیک روی تصویر/پیش‌نمایش محصول فعال است.
- فقط **یک** دکمه بستن وجود دارد.
- دکمه بستن در گوشه چپ بالای تصویر قرار دارد.
- قیمت و واحد پولی محصول تک‌قیمتی در مرکز پیش‌نمایش قرار می‌گیرند.

### کنترل تعداد
- کنترل تعداد سه بخش مستقل دارد: کم‌کردن، عدد، زیادکردن.
- عدد تعداد دقیقاً وسط بخش مرکزی قرار می‌گیرد.
- جهت عدد مستقل از RTL صفحه کنترل شده تا اعداد فارسی/لاتین به یک سمت کشیده نشوند.

### سفارشات دریافتی
- خلاصه تعداد با قالب: **تعداد - X عدد**.
- تعداد هر قلم نیز با قالب **تعداد - X عدد** نمایش داده می‌شود.
- مدیر می‌تواند سفارش را باز کند و تعداد اقلام را کم/زیاد کند.
- اگر تعداد همه اقلام به صفر برسد، سفارش لغوشده می‌شود.
- مدیر می‌تواند کل سفارش را لغو کند.
- تغییرات سفارش در تاریخچه سفارش ثبت می‌شوند.
- در صورت فعال بودن integration و وجود base URL، تغییر سفارش با PATCH به API مرکزی نیز ارسال می‌شود.

## قواعد UI تثبیت‌شده
- Mobile-first.
- Glassmorphism با زمینه آبی/سرمه‌ای و accentهای cyan/violet/coral.
- منوی دسته‌ها در سمت راست.
- کارت‌های محصول با تصویر و کنترل سفارش مستقل.
- قیمت و کنترل تعداد نباید با هم باعث جابه‌جایی سطر شوند.
- محصول بدون تخفیف نباید کادر قیمت اصلی قرمزِ خالی داشته باشد.
- قیمت تخفیف‌دار و قیمت اصلی باید هر دو کامل و بدون clipping نمایش داده شوند.
- مبلغ نوار پایین نباید از کادر خارج شود.
- وضعیت سفارش باید داخل pill خودش کامل و خوانا و وسط‌چین باشد.

## منطق سفارش
وضعیت‌های اصلی سفارش:
- جدید
- تأیید شده
- در حال آماده‌سازی
- آماده
- تحویل شده
- لغو شده

مدیر می‌تواند وضعیت را تغییر دهد، سفارش را ویرایش کند یا لغو کند.

## نکات مهم برای توسعه بعدی
- قبل از افزودن CSS جدید، patchهای قبلی بررسی شوند تا قوانین متضاد ساخته نشود.
- برای اصلاح UI قیمت/تعداد، ابتدا V34 بررسی شود و از ایجاد patch پراکنده روی V6 خودداری شود.
- منطق سفارش و UI باید از هم جدا نگه داشته شوند.
- LocalStorage برای fallback است؛ در استقرار واقعی API مرکزی منبع حقیقت سفارش باشد.
- کلیدها و اطلاعات حساس زعفران نباید در کد سمت مرورگر hard-code شوند.
