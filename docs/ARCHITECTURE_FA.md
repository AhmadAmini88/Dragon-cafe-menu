# معماری Dragon Game Café

نسخه فعلی پروژه برای تبدیل منوی QR به سیستم سفارش‌گیری طراحی شده است.

## جریان اصلی

`QR میز → منوی موبایل → سبد خرید → ثبت سفارش → Backend مرکزی → پنل حسابدار / آشپزخانه → Bridge زعفران`

## نقش‌ها

### مشتری
- بدون نصب اپلیکیشن
- QR اختصاصی میز
- مشاهده منوی زنده
- افزودن افزودنی و یادداشت
- سبد خرید
- ثبت سفارش
- مشاهده وضعیت سفارش

### حسابدار / مدیر
- مشاهده سفارش‌های زنده
- تغییر وضعیت سفارش
- مدیریت محصولات و دسته‌ها
- آپلود لوگو و عکس‌ها
- مدیریت میزها و لینک QR
- مدیریت دستگاه‌های PS5/PC/Xbox/VR
- ارسال سفارش به Bridge زعفران

### آشپزخانه
- صف سفارش‌های فعال
- تغییر وضعیت: جدید → تأیید → در حال آماده‌سازی → آماده → تحویل
- نمایش بصری زمان/وضعیت

## API مرکزی

- `GET /health`
- `GET /api/orders`
- `POST /api/orders`
- `GET /api/orders/:id`
- `PATCH /api/orders/:id`
- `POST /api/zafaran/push`
- `GET /api/settings`
- `POST /api/settings`

## اصل مهم

منوی مشتری نباید مستقیم به دیتابیس زعفران وصل شود. بین منو و زعفران باید Bridge قرار بگیرد تا اعتبارسنجی، ثبت تاریخچه و کنترل خطا انجام شود.

## وضعیت اتصال زعفران

آدرس واقعی Bridge زعفران باید براساس نسخه نصب‌شده و روش اتصال مجاز همان نرم‌افزار تنظیم شود. پروژه نباید API حدسی یا داخلیِ تأییدنشده تعریف کند.
